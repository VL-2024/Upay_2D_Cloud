# УПАЙ 2D (UPAY 2D)

Мобильная 2D-лотерея «Упай» — часть линейки «X2 LOTO» (см. сестринскую игру
[Khan1_2D_Cloud](../Khan1_2D_Cloud), Ордо/Чүкө, тот же LMS-контракт и общий
бренд). PixiJS для сцены/анимации, чистый JS (ES-модули) без сборки —
статический сайт.

Текущая версия: **0.3.0-alpha** (`src/config.js` → `CONFIG.version`).

## Игровой процесс

Раунд — до 7 бросков чуко-битой:

1. **Этап 1** — 3 броска. Нужно выбить все 3, чтобы собрать **1 УПАЙ**.
2. **Этап 2** — ещё 3 броска (только если этап 1 пройден полностью). Все 3 —
   **2 УПАЙ**.
3. **Финальный удар по Хану** — только если оба УПАЙ собраны (6 из 6).

Игрок выбирает чуко-биту и перетягивает её к чуко того же цвета/позы —
либо просто жмёт кнопку «Бросок N/3», которая бросает случайную фишку из
тех, у кого есть пара (без пары — не выбирается). Итог каждого броска
определён заранее сценарием билета (см. ниже) — игра только
визуализирует его, не выбирает исход сама.

### Таблица выплат

| Выбито чуко | Хан | Множитель |
|---|---|---|
| 0 | — | ×0 |
| 1 | — | ×0,2 |
| 2 | — | ×0,5 |
| 3 (1 УПАЙ) | — | ×1,5 |
| 4 | — | ×3 |
| 5 | — | ×5 |
| 6 (2 УПАЙ) | устоял | ×10 |
| 6 (2 УПАЙ) | выбит | ×500 |

Таблица в модалке «Инфо → Таблица выплат» строится программно из
`getPayoutTable()` (`src/scenario-engine.js`), а не хранится отдельным
текстом — значит не может разойтись с реальными правилами.

## Структура проекта

```
index.html              разметка, все модалки и дев-панели
src/
  main.js                вся логика игры (state, рендер, анимации, LMS-вызовы)
  config.js               CONFIG: номиналы, сцена, LMS-настройки, автоигра
  scenario-engine.js       ScenarioEngine — состояние раунда + таблица сценариев
  i18n.js                  словарь RU/EN/KG/ZH, tr()
  rules-content.js          текст «Как играть» (отдельно от кода, редактируется без main.js)
  lms-adapter.js            интеграция с LMS (см. ниже)
  styles.css                вся вёрстка, включая CSS-переменные --v-* (см. ниже)
assets/
  chuko/, khan/, ref/       спрайты и фон/ковёр
  logo.png                  логотип X2 LOTO (топбар, тот же файл что в Khan1_2D_Cloud)
  vendor/                   PixiJS (локальная копия, без CDN/npm)
docs/
  LMS-Integration-spec.md            контракт postMessage + X2_LMS_INIT
  PayTicket-API-spec-for-backend.md  спецификация эндпоинта PayTicket для бэкенда
```

Сборки нет — `index.html` подключает `src/main.js` как `type="module"`
напрямую. Кэш-бастинг через `?v=0.3.0` на всех `<script>/<link>` и
внутренних `import`.

## Запуск локально

Нужен любой статический HTTP-сервер (ES-модули не грузятся с `file://`):

```
python3 -m http.server 8080
```

либо двойным щелчком `start_upay.bat` (Windows) / `start_upay.ps1`
(PowerShell) — оба поднимают сервер на порту 8080 и открывают браузер.

## LMS-интеграция

Игра работает в двух режимах, переключаемых `CONFIG.lms.mock` в
`src/config.js` (по умолчанию `true`) или параметром URL `?mock=false`:

- **mock (по умолчанию)** — вся покупка билета эмулируется локально в
  `src/lms-adapter.js`, реальный бэкенд не нужен, игра полностью играбельна
  сама по себе.
- **боевой режим** (`?mock=false` или `CONFIG.lms.mock=false`) — при
  старте ждёт `X2_LMS_INIT` через `postMessage` от родительского окна
  (LMS открывает игру в `<iframe>`), а «Новая игра» дёргает `PayTicket` —
  см. `docs/LMS-Integration-spec.md` и
  `docs/PayTicket-API-spec-for-backend.md`. Игра никогда не считает
  выигрыш сама — баланс и множитель приходят из ответа `PayTicket`.

**Перед боевым встраиванием обязательно:**
- вписать реальный `CONFIG.lms.endpoints.lms` (сейчас там dev-заглушка);
- заполнить `CONFIG.lms.allowedParentOrigins` конкретными доменами LMS —
  по умолчанию пусто, и `postMessage` от любого origin молча
  отклоняется (fail-closed).

Билет НЕ покупается автоматически при загрузке страницы — только по
нажатию «Новая игра» / «Автоигра».

## Локализация

`src/i18n.js` — плоская таблица `{key, RU, EN, KG, ZH}`, без вложенных
объектов по языкам; отсутствующая колонка у конкретной строки падает на
RU, а не на пустую строку. Применяется через `data-i18n` в разметке и
`tr(key)` в коде. Переключатель языка — одна плашка с текущим кодом и
выпадающим списком (не 4 отдельные кнопки).

## Настройка сцены и размеров (дев-инструменты)

Два временных дев-тула в левом верхнем углу, под логотипом:

- **⚙ Настройка сцены** — размер/положение чуко, Хана, ковра, кучки
  (пишет в `CONFIG.scene`).
- **Aa Шрифты и кнопки** — живая настройка размеров шрифтов, высоты
  панелей и их вертикального сдвига через CSS-переменные `--v-*` в
  `styles.css` (`:root` — десктопный набор, `@media(max-width:700px)` —
  отдельный мобильный, т.к. `.shell` на десктопе — фиксированный холст
  941px, уменьшенный `transform:scale()` под высоту окна, а на телефоне
  рендерится в свою реальную ширину без масштабирования, так что
  одинаковые px по-разному выглядят на разных экранах). Кнопка
  «Копировать» кладёт в буфer готовый блок `:root{...}` с пометкой,
  какой из двух наборов скопирован.

Оба тула — рабочие инструменты для дальнейшей донастройки, не мусор для
удаления «после релиза» без явной причины.
